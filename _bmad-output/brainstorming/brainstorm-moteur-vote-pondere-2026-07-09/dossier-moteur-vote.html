LE MOTEUR DE VOTE PONDÉRÉ

Le composant qui élit, à chaque message, la personnalité qui voix la réponse. Objectif : déterministe, testable, tunable — vivant comme un essaim, prévisible comme une machine.
PRINCIPE · signaux mous (poids) + règles dures (gates) NATURE · fonction pure, sans LLM DÉCISIONS · 8

Étapes 1→3 = le moteur, pur et testable. Le LLM n'intervient qu'à l'étape 5 pour mettre en voix la perso déjà choisie — c'est le split 80/20 qui protège la latence <5s et le faible taux de crash. En mode dégradé, l'étape 5 bascule sur des phrases pré-écrites : la perso reste élue par le moteur.

02La formule de score

Pour chaque personnalité p qui passe les gates, on calcule un score. Chaque terme est normalisé 0→1, chaque poids W est réglable en YAML.

S(p) = Wₜ·T(p) + Wₖ·K(p) + Wc·C(p) + Wᵢ·I(p) + Wₒ·O(p) + Wₑ·E(p)

03Les gates durs

Ce ne sont pas des poids : ce sont des filtres qui s'appliquent avant/après le score. Ils garantissent que ZAX n'est jamais imprévisible.

Kill-word (DISJ-SPEC). Le mot qui arrête l'active → S(active) = −∞, et gros bonus à sa cible EXIT. La coupure sèche, déterministe.
Gate TIME. Un challenger ne peut destituer l'active que si celle-ci a tenu ≥ son TIME (échanges min). Anti-nervosité.
ORGA-ACTV = 0. Perso désactivée : exclue du vote, point.
Orga force. Override total : fixe la perso, ignore tous les scores, avec verrou de durée optionnel. Admin
Défaut ultime. Si tout est gaté / aucun signal : plancher d'ouverture, puis le Gardien en dernier recours (panique).

04La sélection & les 4 transitions

On trie par S(p). Le vainqueur voix la réponse ; le second, s'il est proche et compatible, murmure en fond.

  • Voix dominante = argmax S(p). Égalité tranchée par PRIO (0 = dieu).
  • Voix de fond = runner-up si S₂ ≥ S₁ − δ et combo autorisé → une phrase parasite qui annonce la prochaine bascule (foreshadowing mécanique).
  • Pas de switch si vainqueur == active (continuité, cas le plus fréquent).
  • Transition classée si vainqueur ≠ active, en 4 grammaires : relève douce (montée progressive) · coupure sèche (kill-word) · fusion (deux voix proches) · effondrement (retour Gardien). Toujours télégraphiée (signature, latence, glitch).

07Le cœur, en pseudocode

function decide(state, message) -> Decision:   # pure, sans LLM
    if state.orga_force and not expired: return forced(state.orga_force)

    signals = analyse(message)          # hard-words, embeddings, faction/perso
    candidates = [p for p in persos if p.ORGA_ACTV]

    for p in candidates:
        p.S = Wt*T(p,signals) + Wk*K(p,state) + Wc*C(p,state) \
            + Wi*I(p,state)/temperature + Wo*O(p,state) + We*E(p,state)

    # --- gates durs ---
    if killword_of(state.active) in signals:
        state.active.S = -INF ; boost(state.active.EXIT)
    if state.active.age < state.active.TIME:
        clamp_below(challengers, state.active.S)   # protège l'active

    winner, second = top2(candidates, tiebreak=PRIO)
    bg = second if second.S >= winner.S - DELTA and compatible(winner,second) else None
    transition = classify(state.active, winner, killword_fired)

    log(scores=candidates, gates_fired, winner, transition, reason)  # météo + oracle test
    return Decision(voice=winner, background=bg, transition=transition)

08Stratégie de test & observabilité

  • Golden tests. decide(state, message) pure → table de cas figés : « ce message dans cet état ⇒ cette perso + cette transition ». La régression narrative devient un test unitaire.
  • Fuzzing anti-flip-flop. Séquences de messages contradictoires rapides → assert : nombre de bascules borné (inertie + TIME tiennent).
  • Cas limites couverts. aucun trigger → défaut d'ouverture · tout gaté → Gardien · triggers contradictoires → PRIO + log · troll → surchauffe → Gardien · karma absent → neutre 100/200 · LLM down → perso élue + voix canned.
  • Le log EST l'oracle. Chaque décision journalise scores/gates/raison. Même flux → météo interne orga Admin et débogage narratif temps réel.
  • Tuning sans redéploiement. Poids, TIME, température, forces de trigger en YAML runtime — les scénaristes règlent l'équilibre en live. Admin/superadmin
