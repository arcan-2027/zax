- (technique) started Job to Be Done
- (idea) Ecran orga : liste des conversations en cours + proposition de reponse ZAX par conversation
- (idea) ZAX tourne en quasi-autonomie : reponses auto-validees puis envoyees apres un delai si aucun orga n'intervient
- (insight) Le check orga porte sur deux choses: coherence lore (Fallout + GN) et fidelite a la personnalite active
- (idea) Ecran orga affiche les themes/mots-cles abordes a cote du message propose, pour un scan rapide plutot qu'une lecture complete
- (direction) Auriane: pas experte lore Fallout, ne peut pas juger d'exemples concrets de rupture de lore - point scenariste
- (idea) MVP: liste de themes/mots-cles a la main, score d'embedding de la reponse ZAX contre chaque theme, afficher seulement ceux au-dessus d'un seuil (ex: bunker, IA, goules)
- (technique) started Analogical Thinking
- (idea) Une fois un message envoye, pas de retour en arriere possible pour le joueur, mais un correctif peut arriver dans un dialogue ulterieur (comme un erratum)
- (insight) Les 36h de GN = plusieurs sessions de dialogue distinctes, pas une conversation continue. ZAX doit piocher en BDD l'historique quand un joueur se ré-identifie, comme s'il s'en souvenait
- (technique) started First Principles Thinking
- (insight) Fait irreductible du Gardien: mentalite stricte, ne divulgue pas facilement l'info sans une forme d'accreditation/habilitation
- (idea by coach) Verification unique: interlocuteur identifie/habilite (connu) oui/non - si non ou sujet sensible, eluder par defaut
- (idea) Valide: statut identifie/inconnu (nom+prenom donnes ou non) determine le mode de reponse du Gardien - inconnu = traite comme un etranger
- (technique) started One Feature Only
- (decision) La seule feature indispensable du MVP: le switch identifie/inconnu. Tout le reste (auto-envoi, themes a l'ecran, karma, disjoncteurs elabores) est secondaire/differable
- (technique) started Worst Possible Idea
- (idea) Pire idee: un code unique trouvable a un seul endroit du GN, sans lequel ZAX ne divulgue absolument rien - single point of failure si le code est perdu/rate
- (insight) Principe: aucune info vitale du GN ne doit dependre d'un point d'acces unique - MAIS ca ne s'applique pas au Gardien lui-meme, qui est un outil du GN cense etre strict. C'est aux orgas (forcage/prise de main, deja prevu S6.11) de debloquer le jeu si besoin, pas au Gardien de s'assouplir tout seul
- (technique) started Starbursting
- (idea) Identification = le joueur tape lui-meme son nom dans le chat, pas un scan/badge pour ce mecanisme
- (decision) Recadrage majeur: pas besoin de logique d'identification (deja geree par le badge/profil, DEC-13/S9). Le vrai mecanisme MVP = autorise/interdit, un flag par personnage/perso, defini a la main pour la v1 (ex: perso1 autorise, perso2 interdit)
- (direction) Pause session: Auriane attend un retour de Boris avant de repondre a la question du stockage du flag autorise/interdit
- (idea) Reponse Ou (confirme avec Boris): tables dediees ZAX, prefixees zax_, avec acces lecture/ecriture complet pour ZAX (coherent avec DEC-24 - perimetre zax, pas le domaine Pip-Boy)
- (insight) Scope: le moteur n'a pas besoin de connaitre/encoder la RAISON du changement de flag (quete resolue, etc.) - c'est narratif/orga, arbitraire. Le moteur expose juste un flag mutable
- (idea) V1: mini interface listant les personnages, checkbox par personnage pour afficher/modifier le statut autorise/interdit
- (decision) Point 8 (erratum) n'est pas une feature a dev: le LLM gere nativement la contradiction en diegese (perso bipolaire), rien a construire
- (decision) Point 9 (pas de soupape) confirme non-feature: le LLM suit simplement la conf de la perso, rien a construire
- (decision) MoSCoW - 1. Flag autorise/interdit par personnage: MUST
- (decision) MoSCoW - 2. Mini interface orga (liste persos + checkbox): SHOULD
- (decision) MoSCoW - 3. Tables zax_ dediees en lecture/ecriture: MUST
- (decision) MoSCoW - 4. Ecran orga conversations (liste + reponse proposee): MUST
- (decision) MoSCoW - 5. Auto-envoi apres delai sans intervention orga: MUST
- (decision) MoSCoW - 6. Themes/mots-cles affiches (embedding score vs liste a la main): MUST
- (decision) MoSCoW - 7. Memoire multi-session (historique BDD au retour d'un joueur): SHOULD
- (decision) Confirme: les 5 Must sont le plancher irreductible du MVP - sans eux ce n'est pas un ZAX. Tout le reste (karma, disjoncteurs riches, RAG lore, autres personas...) est hors scope, a ajouter plus tard
- (insight) Synthese: le moteur n'est jamais le point de jugement narratif (lore, disjoncteurs) - il expose signaux/flags, l'orga tranche. Coherent avec DEC-19/20 (app informe, n'arbitre pas). MVP retenu: flag autorise/interdit + tables zax_ + ecran conversations orga + auto-envoi + themes affiches (Must); interface checkbox + memoire multi-session (Should)
