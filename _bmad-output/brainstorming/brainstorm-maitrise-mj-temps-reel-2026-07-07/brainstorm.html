[ VOIR ]

  • Vue cockpit 5 colonnes — une colonne par conversation live, scroll indépendant
  • Résumé IA continu — 1 ligne « où en est cette conversation », mise à jour à chaque échange
  • Code couleur d'urgence — vert = RAS · ambre = validation en attente · rouge = mot-clé critique / timer expiré
  • Picture-in-picture — épingler une conversation chaude en grand, les 4 autres en vignettes
  • Vue « qui parle à qui » — joueur identifié / terminal / personnalité active en temps réel
  • Historique joueur en un clic — le contexte pour décider vite
  • Radar narratif — quels sujets chauds (modules G.E.C.K., mots-clés) abordés sur quel terminal
  • Karma delta live — affichage +/− animé quand une conversation fait bouger le karma
  • Filtre de flux — ne montrer que les messages à mots-clés surveillés
  • Statut personnalité par terminal — avec bouton de forçage direct dans le cockpit, sans navigation

[ VALIDER ]

  • Timer de validation visible en gros — barre qui se vide avant auto-envoi, cliquable pour geler
  • File de validation unifiée — toutes les réponses en attente, triées par temps restant, pas par terminal
  • Bouton « ZAX réfléchit » — gèle le timer et affiche côté joueur une animation de traitement immersive
  • Bibliothèque de réponses pré-approuvées — par personnalité, insérables en un clic puis éditables
  • Suggestions de réponse — le LLM propose 2–3 variantes, l'orga choisit au lieu d'éditer

[ ALERTER ]

  • Alertes à 3 niveaux, canaux distincts — info = badge · warn = bannière · critical = plein écran + son
  • Digest périodique — toutes les 15 min, résumé des terminaux non surveillés
  • Notification mobile — sur le téléphone orga, criticals uniquement
  • Seuils d'escalade configurables — X répétitions d'un sujet interdit = alerte auto
  • Mode nuit / faible activité — dashboard en veille, réveil sonore sur événement

[ COORDONNER & AGIR ]

  • Mode « main levée » — un orga marque « je la gère », verrou souple visible des autres
  • Journal de bord orga — notes horodatées partagées (handover de relève)
  • Timeline de la partie — chronologie des événements majeurs (ouvertures, G.E.C.K., interventions)
  • Bouton panique par terminal — coupe ZAX + message d'attente immersif en un clic
  • Métriques de charge orga — validations/h, temps moyen — pour calibrer le timer X de DEC-04
INSIGHTLe timer d'auto-envoi est LA pièce maîtresse UX : il définit le rythme du jeu entier. Investir dans son réglage — par terminal et par personnalité.
TECHNIQUE 02

Cross-Pollination — balayage des fréquences

Interception de 11 métiers de la supervision temps réel. 25 signaux captés et traduits pour la salle orga.
▚ CASINOEYE-IN-THE-SKY · 104.7
  • Replay instantané des 5 dernières minutes d'une conversation — voir ce qu'on a raté
  • Joueurs VIP — marquer les porteurs d'intrigue, leurs conversations remontent en priorité
  • Comptage de cartes — détection du joueur qui farm le karma en répétant mécaniquement les sujets positifs, alerte anti-exploit
▚ URGENCESSALLE DE TRIAGE · 91.2
  • Score de triage auto — enjeu narratif + risque, ordonne la file de validation
  • Code blue — bouton d'appel à renfort qui ping tous les orgas connectés
  • Tableau de garde — qui couvre quel créneau, passation avec checklist de handover
▚ CONTRÔLE AÉRIENTOUR + APPROCHE · 121.5
  • Deux écrans, deux rôles — vue « approche » globale et vue « tour » conversation active
  • Readback — toute action de forçage est reformulée (« Vous forcez LE GARDIEN sur T3 — confirmer ») contre les erreurs de fatigue
  • Strips — chaque conversation est une carte kanban temps réel : à surveiller / en cours / à valider / résolu
▚ RÉGIE TVDIRECT · 88.8
  • Prochain plan — préparer une prise de main pré-écrite, la lancer au bon moment
  • Talkback — canal de chat interne orga-orga intégré au dashboard
  • Conducteur — script de session (événements narratifs à horaires cibles) avec le « où en est-on »
▚ CUISINECOUP DE FEU · 76.3
  • Expeditor — un chef de passe qui ne valide rien mais dispatche les validations aux orgas disponibles
  • « 86 it » — marquer un sujet interdit à chaud : nouveau mot-clé interdit en 2 clics depuis une conversation
▚ DISPATCH 911PRIORITÉ · 112.0
  • Localisation d'abord — toute alerte affiche TOUJOURS terminal + joueur + personnalité avant le contenu
  • Scripts — arbres de réponse pré-établis pour les situations connues (imposteur, mort qui parle, spam)
▚ ESPORTSOBSERVER · 99.9
  • Caméra auto — le dashboard affiche en grand la conversation la plus intéressante (score activité + mots-clés)
  • Highlights — bookmark automatique des moments à fort karma delta, pour le débrief
▚ STAGE MANAGERCÔTÉ COUR · 83.1
  • Cue sheet — les déclencheurs narratifs (signal vert, morse, ouvertures) sont des cues numérotés avec bouton GO
  • Show must go on — mode dégradé granulaire : T2 en réponses pré-programmées, les autres en LLM
▚ SOUS-MARINIMMERSION · 20.0
  • Quart silencieux — affichage minimal la nuit, uniquement les alertes, écran sombre : économie d'attention
  • Passation rituelle — le dashboard force un mini-résumé de handover avant de changer d'orga connecté
▚ PARC D'ATTRACTIONSFILE D'ATTENTE · 60.6
  • Wait time — latence LLM en temps réel par terminal : l'orga voit si un joueur attend trop
  • Fiche handler — chaque personnalité a sa fiche « comment la jouer en prise de main », en un clic pendant l'intervention
▚ POMPIERSVIGIE · 18.0
  • Niveau de risque global — indicateur synthétique de pression narrative (activité + alertes + volatilité karma) qui dit à l'orga s'il peut souffler

TECHNIQUE 04

Ship in 60 Minutes — le tri de survie

Si on devait livrer demain matin : que garde-t-on, que coupe-t-on, que fake-t-on, qu'emprunte-t-on ?

█ GARDER

  • Le noyau incompressible jour J : flux des 5 conversations + file de validation avec timer + prise de main
  • La persistance des messages — file d'écritures Supabase, noyau dur jour 1 (règle §6.10 : aucune perte)
  • L'échelle réelle : 5 terminaux max, optimisé pour UN orga fatigué — pas pour la charge

✕ COUPER

  • Vue karma complète → un simple log texte des deltas
  • Édition YAML live → édition fichier + bouton « recharger le harnais » (hot-reload suffit)
  • Stats de session → requêtes SQL à la main dans Supabase Studio
  • Toute scalabilité au-delà du terrain réel

~ FAKER (V1 BRUTE)

  • Métriques LLM/QNAP → un ping vert/rouge « Ollama répond ou pas »
  • Détection de mots-clés → regex / match exact, sémantique plus tard
  • Forçage de personnalité → update de zax_config, 5 boutons bruts, l'UI riche attend
  • Mode dégradé → un gros toggle manuel global, l'auto-timeout vient après
  • Injection de contexte → champ texte brut par terminal
  • Vue terminaux → 5 cartes statut (connecté, joueur, perso active), sans historique
  • Envoi de fichiers → coller un texte/URL, le rendu riche attend
  • Alertes → bannière dashboard uniquement ; son + mobile en itération 2

⇄ EMPRUNTER

  • Chat interne orga → canal Discord / Element existant, pas de talkback intégré en v1
  • Notifications mobiles → webhook ntfy / Telegram plutôt qu'une app dédiée
NON NÉGOCIABLECe qu'on ne peut PAS faker : la persistance des messages. La règle « aucune perte » n'attend pas la v2.
